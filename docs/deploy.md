# Deploying Northline (review-only first)

Northline is a Next.js app that talks to the EXISTING Supabase project (database + private `northline-assets` bucket). Hosting it does not create a second database and never needs the browser to see a secret: every variable below is server-side only (there is no `NEXT_PUBLIC_*`).

## Modes
| | Review-only (first deployment) | Full (later, when you choose) |
|---|---|---|
| `NORTHLINE_STORE` | `supabase` | `supabase` |
| `NORTHLINE_READONLY` | `true` | unset |
| OpenAI / Gemini / image provider keys | **not set** | set |
| Can create / generate / run QA / approve / edit / upload | **No** (UI disabled, server refuses, repo and storage refuse writes) | Yes |

## Safety guards (in code)
- **Production fails closed**: with `NODE_ENV=production` the app refuses to start serving data unless `NORTHLINE_STORE=supabase` and `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `NORTHLINE_ADMIN_PASSWORD`, `NORTHLINE_SESSION_SECRET` are set. `/api/health` returns 503 and lists the missing variable NAMES (never values).
- **Auth cannot be disabled in production**: `NORTHLINE_AUTH_DISABLED` is ignored when `NODE_ENV=production`.
- **Read-only mode** (`NORTHLINE_READONLY=true`): server actions redirect before doing any work; `/api/create`, `/api/n8n/*` and `/api/agents/tick` return 403; the repository and storage wrappers throw on any write (second, independent layer); pages never persist anything while rendering; the UI shows a banner and disables action buttons.

## Environment variables (NAMES ONLY)
Required: `NORTHLINE_STORE`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `NORTHLINE_ADMIN_PASSWORD`, `NORTHLINE_SESSION_SECRET`.
Review-only switch: `NORTHLINE_READONLY`.
Full mode only: `IMAGE_PROVIDER`, `OPENAI_API_KEY`, `OPENAI_IMAGE_MODEL`, `OPENAI_TEXT_MODEL`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `LLM_PRICING_JSON`, `NORTHLINE_WEBHOOK_SECRET`.
Never set in production: `NORTHLINE_AUTH_DISABLED`, `LLM_ENABLE_MOCK`.

## Render (Blueprint in `render.yaml`)
Build `npm ci --include=dev && npm run build`, start `npm start`, health check `/api/health`. See "Render setup steps" below. Rollback = suspend or delete the Render service; Supabase data is unaffected.

## Feature flags (all default OFF; none changes behaviour until set)
| Variable | Effect |
|---|---|
| `NORTHLINE_PAUSE=true` | Emergency pause for image generation (no database needed; overrides the DB flag) |
| `NORTHLINE_GOVERNOR=on` | DB-backed daily image caps, attempt caps and audit (needs migration 0007) |
| `NORTHLINE_DURABLE_JOBS=on` | Durable retry/backoff/BLOCKED semantics + stage gate (needs 0007 + 0008) |
| `NORTHLINE_JOB_STAGE=1..5` | Which job kinds the background worker may start (default 1: `system.*` test jobs only) |
| `NORTHLINE_AUTONOMOUS_GENERATION=on` | Allow machine-triggered (n8n/schedule) generation. Leave OFF until deliberately enabled |

## Supabase connectivity expectations
- The app reaches Supabase over HTTPS (PostgREST + Storage) using the service-role key, **server-side only**. Render needs outbound internet (default) and nothing else; no IP allow-list is required by Supabase.
- `/api/health` is a public liveness check and deliberately does **not** touch the database. To confirm the database is reachable, sign in: the dashboard's Command Center and Productions load real rows (they fail with a visible error if Supabase is unreachable or the key is wrong).
- Pick the Render region nearest your Supabase project (latency is per query). A paused (free-tier idle) Supabase project must be resumed before the app can read.
- Migrations 0001–0008 must already be applied (they are). The first deployment needs **no** database change.

## Render setup steps (first deployment: read-only, review-only)
1. In Render: **New → Blueprint** → connect your GitHub account → select repo `christiancraver123-cloud/northline` → branch `claude/gracious-knuth-kwtmz5` (Render reads `render.yaml` from that branch).
2. Render lists the variables. Enter the three secrets it asks for (never share them in chat):
   - `SUPABASE_URL` — Supabase → Project Settings → API → Project URL
   - `SUPABASE_SERVICE_ROLE_KEY` — same page, the `service_role` key (server-side secret)
   - `NORTHLINE_ADMIN_PASSWORD` — choose a long passphrase; it is the login for the site
   `NORTHLINE_SESSION_SECRET` is generated by Render; the other variables are pre-filled by the blueprint (`NORTHLINE_STORE=supabase`, `NORTHLINE_READONLY=true`, `NORTHLINE_GOVERNOR=on`, `NORTHLINE_DURABLE_JOBS=off`, `NORTHLINE_AUTONOMOUS_GENERATION=off`). **Do not add any OpenAI/Gemini/provider variable.**
3. Plan: the blueprint says `starter` (always-on, paid by Render). You may choose Free in the dashboard instead, but a free instance sleeps after inactivity (slow first load).
4. Create the service and wait for the first build (≈3–6 min). `autoDeploy` is off; redeploy manually.
5. Verify: open `https://<service>.onrender.com/api/health` → `{"ok":true,"store":"supabase","readOnly":true}`; open `/`, sign in with the password; you should see the amber "Read-only mode" banner and the Command Center (governor ON, durable jobs OFF, autonomous generation DISABLED).
6. If health shows `503 misconfigured`, the response lists the missing variable NAMES; fix them in Render → Environment and redeploy.
Rollback: Render → the service → Suspend (or Delete). Supabase data is unaffected.
